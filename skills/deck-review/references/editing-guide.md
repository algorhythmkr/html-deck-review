# 사업계획서·IR 덱 수정 원칙과 함정

여러 차례 피드백 사이클(한 덱에 10~30회 수정)을 돌리며 굳어진 규칙이다.

## 버전 관리

- **수정마다 새 버전 파일**(`_v1.2.html`)을 만든다. 이전 파일은 검토자가 쓴 의견의 기준본이므로 보존한다.
- 피드백은 버전별 파일(`_v1.1_feedback.json`)로 쌓인다. v1.2를 만들 때는 v1.1 피드백만 반영하고, 이전 버전 피드백은 다시 꺼내지 않는다. 버전 파일과 피드백 파일은 짝으로 함께 보관한다.
- 작은 수정 묶음은 `v1.2a`, `v1.2b`처럼 접미사를 붙여도 된다(버전 파싱이 지원한다).
- `<head>`의 changelog 주석에 `v1.2  3p 표 열 추가 · 7p 제목 축약` 식으로 한 줄씩 남긴다. 덱이 자기 이력을 갖게 한다.
- 수정 전 백업이나 중간 산출물(검수 이미지, 임시 스크립트)은 프로젝트의 `temp/` 아래에 둔다.

## 슬라이드 키

- 슬라이드를 **새로 만들면** 내용을 나타내는 새 키(`market-size`)를 준다. 기존 키를 재사용하지 않는다.
- 두 슬라이드를 **합치면** 남는 쪽 키를 유지한다. 사라진 쪽 의견은 `feedback_report.py`에서 orphan으로 나오니, 합친 슬라이드에서 반영 여부를 판단한다.
- 슬라이드 **순서만** 바꿀 때는 키를 그대로 둔다. 번호는 셸이 화면 순서로 다시 매긴다.

## 자주 오는 지시와 실제 할 일

| 지시 | 할 일 |
|---|---|
| “여백이 많다 / 아래가 비었다” | 글자 크기를 키우고 안쪽 여백을 줄인 뒤, 남는 세로 공간은 `flex:1`로 채운다. 그래도 남으면 도식·수치 카드를 추가한다 |
| “내용이 많다 / 간결하게” | 부연 문장을 지우고 표·도식으로 압축한다. 한 장에 밀어 넣지 말고 필요하면 슬라이드를 나눈다 |
| “n번과 m번을 합쳐줘” | 위에 요약 한 줄, 아래에 대비 구조(기존 vs 제안). 세부는 과감히 버린다 |
| “인포그래픽으로” | 인라인 SVG로 그린다. 참고 이미지를 주면 그 배치를 따른다 |
| “내용 변경” | 문구를 다듬는 것이 아니라 내용을 바꾸라는 뜻일 수 있다. 모호하면 확인한다 |
| “모든 슬라이드에서 ○○ 삭제” | 영역 선택자로 패턴(클래스·요소)을 파악하고 덱 전체에서 같은 패턴을 찾아 지운다 |

## 문장 (한국어 사업계획서·IR)

- 슬라이드 제목은 주장 한 문장. 근거는 본문에 둔다.
- 본문은 명사형 개조식(“~함”, “~구축”) 위주. 서술형 “~다”를 섞지 않는다.
- 수치는 출처와 기준 연도를 확인할 수 있어야 한다. 출처는 `deck-meta`의 `sources`나 부록 슬라이드로 모은다.
- 인쇄될 덱은 표지·마무리에도 어두운 전면 배경을 피한다(컬러 인쇄 품질·잉크).

## 함정

- **전역 클래스 충돌**: 슬라이드마다 같은 클래스명(`.row`, `.card`)을 다른 의미로 쓰면 한 곳 수정이 다른 슬라이드를 깬다. 슬라이드 전용 규칙은 `#s05 .card`처럼 슬라이드 ID로 범위를 좁힌다.
- **정적 페이지 번호**: 꼬리말에 `05 / 19`를 직접 써 두면 슬라이드를 끼우거나 지울 때 전부 어긋난다. 삽입·삭제 후에는 전 슬라이드 번호를 다시 매기거나, 번호를 JS로 채운다.
- **여분의 닫는 태그**: `</div>` 하나가 남으면 꼬리말이 슬라이드 밖으로 빠져 다음 슬라이드에 겹친다. `check_deck.py`의 `outside`로 잡힌다.
- **`height:100%` 넘침**: 부모 높이가 정해지지 않은 상태에서 이미지가 넘치는 경우가 있다. `clipped`·`outside` 둘 다 확인한다.
- **CSS 특이도**: 나중에 추가한 규칙이 안 먹으면 기존 규칙의 특이도(`#id .cls`)를 확인한다. `!important` 남발보다 범위를 맞추는 편이 안전하다.
- **눈 검수만으로 끝내지 않는다**: 글자 겹침·하단 잘림은 화면 배율 때문에 놓치기 쉽다. 수정 후에는 항상 `check_deck.py`를 돌린다.
